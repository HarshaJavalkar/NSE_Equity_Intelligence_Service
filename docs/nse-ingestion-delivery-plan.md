## Recommended Production Flow

1. **Discover availability, not just the clock.** Treat 7:30 PM India Standard Time as the start of an expected release window, not a guarantee that every report is already published. Check the official NSE CM reports surface and retry within a bounded window, including special weekend sessions.
2. **Use one pipeline.** Manual fetch, scheduled fetch, and startup catch-up should all call the same discovery, download, validation, archive, enrichment, and Redis publication service. Only the trigger differs.
3. **Stage before replacing.** Download into a temporary run directory, validate that the required report set is complete, and only then atomically switch the active local date directory. Preserve the currently active files if download or validation fails. This meets the replace-on-success requirement without risking data loss during a failed fetch.
4. **Keep raw and enriched data separate.** Store raw NSE files and a manifest under `server/assets/data/nse-<trade-date>` (or the repository-approved equivalent). Store canonical enriched security snapshots and indices in Redis. Do not make APIs parse raw files on demand.
5. **Enrich by stable identity.** Resolve reports primarily by ISIN/security code, with explicit handling for report-specific symbol aliases and missing identities. Keep report-level provenance and do not merge same-named columns without source-specific mapping.
6. **Publish atomically.** Build and validate the new version first, write versioned Redis snapshots/indices, verify them, then switch the latest-dataset pointer. Keep prior versions for a bounded retention period and clean them only after a successful publication.
7. **Separate triggers from user requests.** A scheduler/worker must run without user traffic or user tokens. The manual UI should use an operator-authenticated endpoint; never put the internal service token in frontend code. Protect both scheduled and manual runs with a distributed per-trade-date lock.
8. **Use startup as recovery, not as the schedule.** On server startup, inspect dataset freshness and queue a catch-up only if the active data is absent or stale. Do not unconditionally download every report every time an API replica restarts. Keep the daily scheduler active regardless of requests.

## Current Evidence

- Manual archive endpoints: `server/src/control-plane/routes.js` (`POST /api/v1/developer/nse/ingestion`, `GET /api/v1/developer/nse/ingestion` with optional date/force flags) and internal trigger in `server/src/app.js`.
- Report archive location and replacement behavior: `server/src/ingestion/nse-report-archive.js` (`server/assets/data/nse-<date>` with staged replacement and a manifest).
- Discovery, parsers, and supported report sources: `server/src/ingestion/nse-report-discovery.js`, `server/src/ingestion/nse-source-mappers.js`, `server/src/config/nse-source-registry.js`.
- Full report enrichment and dataset builder: `server/src/ingestion/nse-report-enricher.js` (explicit parsers for VaR, MTO, Collateral, CSQR, FCM, Volatility, Short Selling, Surveillance, 52-Week, PE; non-security classification; series preference), `server/src/ingestion/nse-dataset-builder.js` (schema version 1.2 with first-class domain projections on `market` and full raw `reports`).
- Redis versioned publication, atomic pointer swap, and bounded retention cleanup: `server/src/ingestion/redis-dataset-publisher.js` (version tracking in `nse:eq:dataset:versions` and SCAN deletion of obsolete versions).
- Job orchestration, crash recovery, and deduplicated scheduling: `server/src/ingestion/nse-ingestion-coordinator.js` (orphaned job recovery, `isDateCompleted`), `server/src/ingestion/nse-ingestion-scheduler.js` (release window 19:30-23:59 IST, completion deduplication, bounded 12 retries).
- Operator email allowlist: `NSE_INGESTION_OPERATOR_EMAILS` configured in `.env` and `.env.example`, with wildcard and verified developer email support.
- Angular UI manual-fetch component: `whyfolioNseDataUI/src/app/components/nse-ingestion` and `DeveloperApiService.startNseIngestion`.
